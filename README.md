# Udit Sharma — side-scrolling portfolio

An interactive portfolio that scrolls **left to right** like a platformer. The
page scrolls vertically as normal; that scroll is translated into horizontal
movement through a pinned world, so trackpads, wheels, touch, keyboard and the
scrollbar all work without any event hijacking.

## Stack

| | |
|---|---|
| Framework | Next.js 16 (App Router) + React 19 + TypeScript |
| Styling | Tailwind CSS v4, plus hand-written pixel primitives in `app/globals.css` |
| Scroll engine | GSAP `ScrollTrigger` (pin + manual transform) |
| Smoothing | Lenis |
| Fonts | Press Start 2P (display/HUD), VT323 (body) |
| Design system | Generated by the `ui-ux-pro-max` skill — see `design-system/` |

## Design system

`design-system/udit-portfolio/MASTER.md` is the generated source of truth
(category: **Arcade & Retro Game**). Two deliberate deviations from it:

- It specifies Brutalism's "no smooth transitions (instant)". Ignored — game
  feel depends on eased motion, and instant state changes are themselves
  flagged as an anti-pattern elsewhere in the same ruleset.
- It specifies a fully dark palette. Applied to the **UI chrome** (panels,
  chips, HUD) but not the world, which would have killed a daylight
  platformer. Instead dark is the *destination*: see below.

## Time of day

`lib/timeOfDay.ts` holds five phases (dawn → morning → golden hour → dusk →
night). Scroll progress interpolates between them and GameWorld writes the
result straight to CSS custom properties on the container, so sky, mountains,
hills, grass and ground all recolour without a React render. You arrive at the
castle under stars.

## How it works

`components/GameWorld.tsx` pins a full-viewport container and translates a
`w-max` flex track horizontally as you scroll. Six layers move at different
rates: stars `0.05`, mountains `0.18`, clouds `0.28`, hills `0.45`, trees
`0.72`, world `1.0`, foreground tufts `1.15`. The foreground running *faster*
than the world is what actually sells the depth. The character is
camera-locked — the world moves past him — and his run/idle state and facing
direction come from `ScrollTrigger`'s scroll velocity.

Three things worth knowing if you edit this:

- **Reveals are driven by scroll position, not `IntersectionObserver`.** The
  track is pinned with `position: fixed` and only its transform changes;
  browsers don't reliably recompute intersections for that.
- **The project dialogs are portalled to `<body>`.** `position: fixed` inside a
  transformed ancestor anchors to that ancestor, not the viewport.
- **Never give a panel in the world `overflow-y: auto`.** A scrollable element
  sitting in the middle of a scroll-driven page swallows the wheel and the
  world stops moving. Content must fit instead.

## Editing content

**All copy lives in `content/profile.ts`.** Don't edit components to change
text. Checkpoints render in array order; `projects` attach to a checkpoint via
`afterCheckpoint` and become a floating **`?` block** after it — hit it and the
project pops out. (These were green pipes originally; a pipe promises a second
underground level, which this site doesn't have. A block promises an item,
which is what a project card actually is.)

Layout constraints to respect:

- **5 power-ups per checkpoint.** More still render, but the chip row gets busy.
- **Cards must fit the viewport** — they do not scroll (see above). Long bullet
  lists (>2) automatically go two-column to keep height down. If you add a lot
  of copy to one level, check it at ~700px viewport height.

### About the character animation

It is one static front-facing pose, so there is no walk cycle to play. Movement
is conveyed by a bob, a lean in the direction of travel, and a contact shadow
that tightens as he rises. If you ever want real locomotion, that needs either
a side-on sprite sheet or a Rive rig — see `components/Character.tsx`.

## Responsive

At `lg` (1024px) and up you get the game. Below that, `components/MobileWorld.tsx`
renders the same content as a plain vertical page — no pinning, no horizontal
scroll. Both are server-rendered, so all the text is in the HTML for search
engines and screen readers.

## Deploying to Vercel

Zero config — it's a standard Next.js App Router project with no server-side
dependencies, no database, and no environment variables required.

1. Vercel → **Add New… → Project** → import this repository.
2. Leave every setting at its default. Vercel detects Next.js, runs
   `npm install && next build`, and serves it. Framework preset: **Next.js**.
3. Deploy.

Notes:

- **No env vars are needed.** Optionally set `NEXT_PUBLIC_SITE_URL` to a custom
  domain so social link previews point at it; otherwise the app falls back to
  `VERCEL_PROJECT_PRODUCTION_URL`, which Vercel provides automatically.
- `.nvmrc` pins Node 22; `package.json` requires `>=20.9.0`.
- Every route is statically prerendered, so it runs on the free tier with no
  serverless invocations.
- `app/opengraph-image.jpg` is picked up automatically for link previews.
